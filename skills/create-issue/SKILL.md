# GitHub 이슈 생성 스킬

자율적인 PR 생명주기 관리를 위한 에이전트 지침이 내장된, 종합적이고 구조화된 GitHub 이슈를 생성한다.

## 개요

이 스킬은 GitHub 이슈를 그 자체로 완결된 작업 패킷으로 생성한다. 각 이슈에는 다음 내용이 포함된다.

1. 명확한 범위를 포함한 **문제/기능 명세**
2. 타입, 스키마, API 설계를 포함한 **기술 명세**
3. 테스트 우선 사이클로 구성한 **TDD 구현 계획**
4. **수용 기준** 체크리스트
5. 전체 PR 생명주기(구현 → 리뷰 → 머지)를 위한 **에이전트 지침**

## 사용법

```
/create-issue
```

## 대화형 흐름

판단할 수 있는 문맥이 있으면 사용자에게 1,2단계를 스킵하고 다음 단계로 넘어간다.

### 1단계: 이슈 유형

판단할 수 있는 문맥이 있으면 사용자에게 다시 묻지 않고 다음 단계로 진행한다.

대화 문맥이 없거나 유형을 판단할 정보가 부족한 경우에만 사용자에게 묻는다.

```
어떤 유형의 이슈인가요?
1. Feature - 새로운 기능
2. Bug - 동작이 잘못된 문제
3. Refactor - 기존 코드 개선
```

### 2단계: 간단한 설명

```
문제나 기능을 간단히 설명해 주세요. (1~2문장)
```

### 3단계: 맥락 수집

```
참조해야 할 관련 파일, 서비스 또는 이슈가 있나요?
(또는 "코드베이스 탐색"이라고 말하면 직접 조사합니다.)
```

### 4단계: 이슈 생성

SwayLoop 조직에서 상속받는 표준 `agent-task.md` 템플릿을 사용해 전체 이슈를 생성한다.

1. `gh` CLI 설치 여부를 확인한다. 설치되어 있지 않으면 사용자에게 설치 후 다시 실행하도록 안내한다.
2. `scripts/create-issue.sh template`을 실행해 `swayloop/.github`의 최신 템플릿을 가져온다.
3. 현재 대화 문맥과 코드베이스 조사 결과를 사용해 템플릿을 채운다.
4. 알 수 없는 내용은 추측하지 않고 선택 항목을 비워 두거나 제거한다.
5. 필수 항목인 `요약`과 `수용 기준`은 반드시 작성한다.
6. `.github/labels.yml`과 대상 저장소의 라벨 목록을 확인한다.
7. 이슈 유형에 맞는 `type:` 라벨을 반드시 하나 추가하고, 그 밖의 라벨은 문맥상 필요한 경우에만 추가한다.
8. 선택한 라벨과 함께 이슈를 생성한다.
9. 생성된 이슈를 다시 조회해 본문과 라벨이 적용되었는지 확인한다.
10. 생성된 이슈 번호와 URL을 사용자에게 반환한다.
11. `issue` 스킬에 생성된 이슈 번호를 전달해 작업 브랜치를 만든다.
